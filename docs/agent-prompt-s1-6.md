## هدف

ساخت احراز هویت کاربران هر دیتابیس شرکت (ورود، توکن دسترسی، refresh چرخشی، خروج، نشست‌ها، تغییر رمز، قفل حساب)، گاردهای پیش‌فرض‌امن (JWT، نوع کاربر، تغییر رمز اجباری، مجوز) و رجیستری مجوزها. ساخت کاربر و گروه و Record Rule (CRUD) در S1.7 و S1.8 است؛ UI ورود در S1.12.

## تصمیم‌های طراحی (قفل‌شده)

1. **امن‌بودن پیش‌فرض:** یک `JwtAuthGuard` سراسری (`APP_GUARD`) همه‌ی مسیرها را می‌بندد؛ فقط مسیرهای با `@Public()` (health، login، refresh، dev، مسیرهای public دیتابیس) و مسیرهای `/v1/admin/*` (گارد Master جدا) باز می‌مانند. مسیر فراموش‌شده‌ی بدون دکوراتور باید **بسته** باشد، نه باز.
2. **نوع کاربر پیش‌فرض: `INTERNAL`.** مسیرهای `/v1/portal/*` فقط `PORTAL`. توکن ادمین (`aud=admin`) برای مسیر tenant و توکن کاربر برای مسیر ادمین هرگز معتبر نیست.
3. **ایزولاسیون:** `claims.db` باید دقیقاً با دیتابیس درخواست یکی باشد. ترتیب Resolver: Host ← هدر `X-Database` ← (در نبود هر دو) claim `db` از **payload رمزگشایی‌شده‌ی توکن، فقط برای انتخاب دیتابیس**؛ اعتبار واقعی (امضا) را `JwtAuthGuard` می‌سنجد و عدم تطابق ← ۴۰۱. تا قبل از تایید امضا هیچ داده‌ای نشان داده نمی‌شود.
4. **Refresh Token چرخشی با تشخیص استفاده‌ی مجدد** و پنجره‌ی مهلت کوتاه برای رقابت چند تب (تصمیم ۷).
5. **پاسخ ورود یکسان:** نام کاربری ناموجود، رمز غلط، کاربر غیرفعال و قفل‌شده برای کلاینت **از هم قابل‌تشخیص نباشند** (وضعیت، بدنه، هدرها، و از نظر زمان: همیشه یک verify argon2، با هش ساختگی برای کاربر ناموجود).
6. **Fail-closed:** قطع Redis ← مسیرهای احراز هویت و بررسی توکن ۵۰۳ (نه ادامه‌ی بدون بررسی).
7. **لغو فوری:** توکن دسترسی ۱۵ دقیقه‌ای است ولی بعد از خروج، تغییر رمز یا غیرفعال‌سازی باید **فوراً** رد شود (لیست ابطال Redis).

## خروجی‌های لازم

### ۱. مایگریشن `0002_auth_sessions` (اولین مایگریشن واقعی بعد از baseline)

SQL دستی، رو به جلو، با بازبینی؛ افزودن به `sessions`: `rotated_at timestamptz null`، `revoked_reason text null`، `family_created_at timestamptz not null default now()`، `last_ip text null`. شاخص‌های لازم برای جستجوی خانواده و نشست‌های فعال کاربر. `schema.prisma` همگام شود و `db:check-drift` سبز بماند. **باید روی دیتابیس‌های موجود (erp_dev، دیتابیس‌های ساخته‌شده با Database Manager) با `upgradeAll` بدون خطا اعمال شود** و تست شود (از جمله دیتابیس خالی از صفر). مایگریشن‌های ساختگی تست‌های قبلی خراب نشوند.

### ۲. توکن‌ها

- **Access JWT:** HS256، کلید `JWT_SECRET`، claimها: `iss=bodo`، `aud=bodo-user`، `sub`، `typ`، `db`، `sid`، `mcp` (تغییر رمز لازم)، `iat`، `exp` (۱۵ دقیقه، قابل‌تنظیم). شناسه‌ی کلید `kid` و پشتیبانی از کلید قبلی (`JWT_SECRET_PREVIOUS`) برای چرخش بدون قطع نشست. `alg: none` و الگوریتم‌های دیگر رد شوند؛ تنها HS256 صریح.
- **Refresh:** ۴۸ بایت تصادفی؛ قالب توکن `<sessionId>.<secret>`؛ در دیتابیس فقط `HMAC-SHA256(secret, REFRESH_TOKEN_PEPPER)`؛ مقایسه‌ی زمان‌ثابت.
- هر refresh یک ردیف نشست **جدید** در همان `familyId` می‌سازد و قبلی را `rotated_at` می‌زند. استفاده از توکن چرخانده‌شده **خارج از مهلت** (`REFRESH_REUSE_GRACE_MS`، پیش‌فرض ۱۰۰۰۰) ← کل خانواده باطل (`revoked_reason='reuse_detected'`)، ثبت Audit و ۴۰۱. **داخل مهلت** ← ۴۰۱ بدون ابطال خانواده (برای رقابت دو تب؛ تب دوم با کوکی تازه دوباره تلاش می‌کند).
- طول عمر: refresh لغزان ۳۰ روز، سقف مطلق خانواده ۹۰ روز (`family_created_at`)، حداکثر ۱۰ نشست فعال برای هر کاربر (قدیمی‌ترین خانواده باطل شود).
- **لیست ابطال Redis** (`tenantKey`): کلید `sid` ابطال‌شده با TTL برابر بیشینه‌ی عمر توکن؛ و `revoked-before` برای هر کاربر (توکن‌هایی با `iat` قدیمی‌تر رد شوند) برای «خروج از همه»، تغییر رمز و غیرفعال‌سازی.

### ۳. مسیرها (`/v1/auth`)

| متد    | مسیر               | توضیح                                                                                                                                                                        |
| ------ | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/login`           | `{username, password}`؛ پاسخ: `accessToken`، `expiresIn`، `user` (`id, username, fullName, type, mustChangePassword`). refresh فقط در کوکی (وب) یا بدنه (`X-Client: mobile`) |
| POST   | `/refresh`         | کوکی یا بدنه؛ چرخش                                                                                                                                                           |
| POST   | `/logout`          | نشست جاری                                                                                                                                                                    |
| POST   | `/logout-all`      | همه‌ی نشست‌های کاربر                                                                                                                                                         |
| GET    | `/me`              | کاربر، مجوزها، `company.name` و ارز پیش‌فرض، نشست جاری                                                                                                                       |
| POST   | `/change-password` | `{currentPassword, newPassword}`؛ سایر نشست‌ها باطل، نشست جاری با توکن تازه ادامه می‌دهد                                                                                     |
| GET    | `/sessions`        | نشست‌های فعال خودم (بدون هش)                                                                                                                                                 |
| DELETE | `/sessions/:id`    | ابطال یکی از نشست‌های خودم (نه دیگران)                                                                                                                                       |

- **کوکی refresh:** نام `bodo_rt_<slug>` (جدا برای هر دیتابیس تا دو شرکت در یک مرورگر هم‌دیگر را بازنویسی نکنند)، `HttpOnly`، `SameSite=Strict`، `Path=/v1/auth`، `Secure` با `COOKIE_SECURE` (پیش‌فرض production روشن؛ dev روی `http://localhost` مجاز).
- **CSRF:** روی `/refresh` و `/logout` با کوکی، هدر `Origin` (یا `Referer`) باید با `CORS_ORIGINS` یکی باشد وگرنه ۴۰۳؛ حالت بدنه (mobile) بدون کوکی است و `Origin` لازم ندارد. توکن دسترسی فقط از هدر `Authorization: Bearer`، هرگز از کوکی.
- فراخوان‌ها `@RateLimit` دارند (بند ۴). همه‌ی ورودی‌ها از `contracts`، پاسخ‌ها بدون هیچ فیلد حساس (`expectNoSecrets`).

### ۴. محدودسازی و قفل

- IP: ۳۰ تلاش ورود در دقیقه برای هر `(db, ip)` و سقف سراسری هر IP.
- `(db, username نرمال‌شده)`: ۵ شکست ← قفل ۱۵ دقیقه‌ای با **۴۲۹ + `Retry-After` یکسان برای کاربر موجود و ناموجود**. در دوره‌ی قفل، حتی رمز درست رد می‌شود.
- برای کاربر موجود `failed_login_count` و `locked_until` هم به‌روز شود (دید مدیر و unlock در S1.7). موفقیت شمارنده‌ها را صفر می‌کند.
- نرمال‌سازی نام کاربری: NFKC، trim، حروف کوچک؛ الگوی `[a-z0-9._-]{3,32}`.

### ۵. رمز عبور

- `@node-rs/argon2` (از S1.4) با پارامترهای قابل‌تنظیم env (پیشنهاد OWASP: `m=19456 KiB, t=2, p=1`)؛ **rehash خودکار** در ورود موفق اگر پارامترها قدیمی‌اند.
- سیاست: NFKC، حداقل ۱۰ و حداکثر ۱۲۸ کاراکتر، نه برابر نام کاربری، نه در فهرست رمزهای رایج (همان سرویس S1.4 را به یک `PasswordPolicy` مشترک ببر). بدنه‌ی بیش از سقف (مثلاً ۱ کیلوبایت برای فیلد رمز) **قبل از هش** رد شود (ضد DoS).
- `must_change_password`: توکن `mcp=true` می‌گیرد و گارد فقط `/auth/me`، `/auth/change-password` و `/auth/logout` را اجازه می‌دهد؛ بقیه ← ۴۰۳ با کد جدید `PASSWORD_CHANGE_REQUIRED` (در `contracts`).
- تایید ورود نباید حلقه‌ی رویداد را بلاک کند (argon2 غیرهمگام).

### ۶. گاردها، دکوراتورها، مجوزها

- گاردهای سراسری به ترتیب: `JwtAuthGuard` ← `UserTypeGuard` ← `PasswordChangeGuard` ← `PermissionGuard`.
- دکوراتورها: `@Public()`، `@InternalOnly()` (پیش‌فرض)، `@PortalOnly()`، `@RequirePermission(code | [codes], { mode: 'any' | 'all' })`، `@CurrentUser()`.
- **رجیستری مجوز:** `registerPermissions([{code, resource, action, module, label}])` در زمان بوت هر ماژول؛ تکراری ← خطای بوت. مجوزهای اولیه‌ی بند ۸.۴ مستند را همین‌جا ثبت کن.
- `PermissionService.getUserPermissions(userId)`: اجتماع مجوز گروه‌های کاربر؛ گروه سیستمی «مدیر سیستم» (`isSystem`) **همیشه همه‌ی مجوزهای ثبت‌شده** را دارد (پویا، شامل مجوزهایی که بعداً ثبت می‌شوند). کش Redis با TTL ۵ دقیقه و `invalidate(userId | all)` (S1.7 و S1.8 صدا می‌زنند).
- `RequestContext` (از S1.5) با `userId` و `userType` پر شود (برای لاگ و Audit).

### ۷. Audit (حداقل)

`AuditWriter.write()` ساده (S1.9 کامل می‌کند) با `audit_logs` (فقط INSERT): `auth.login.success/failure`، `auth.logout`، `auth.logout_all`، `auth.refresh_reuse_detected`، `auth.password_changed`، `auth.lockout`، `auth.session_revoked`. شامل ip، userAgent، requestId، `source`. **هرگز رمز یا توکن.** برای شکست ورود به‌جای نام کاربری خام، فقط هش کوتاه (کاربران گاهی رمز را در فیلد نام کاربری تایپ می‌کنند). علت داخلی شکست (ناموجود/غیرفعال/قفل/رمز غلط) در Audit می‌آید ولی هرگز به کلاینت نمی‌رود.

### ۸. مستندات و ابزار

- README: بخش احراز هویت با نمونه‌ی PowerShell (`Invoke-RestMethod` و `curl.exe`) برای login ← me ← refresh ← logout. مسیر ساخت کاربر برای تست: دیتابیس جدید با `pnpm db:manager create demo --user admin ...` (Provisioning از S1.4 کاربر مدیر را می‌سازد؛ تایید کن این کاربر با همین مسیر قابل‌ورود است).
- OpenAPI: طرح `bearer`، endpointهای auth، و `@Public` ها مشخص.
- ADR-0007 (ساختار توکن‌ها و چرخش، مهلت رقابت، ابطال فوری، قفل یکنواخت، ترتیب Resolver، CSRF، سیاست رمز، مایگریشن ۰۰۰۲).

## تست‌ها (Postgres و Redis واقعی؛ `createTestApp()` مشترک؛ مسیر HTTP واقعی)

**ورود و پاسخ یکسان**

1. موفق: کوکی (`HttpOnly`، `SameSite=Strict`، `Path`، `Secure` بر اساس env) و نبود refresh در بدنه‌ی وب؛ حالت mobile: refresh در بدنه و بدون کوکی.
2. نام کاربری ناموجود، رمز غلط، کاربر غیرفعال و قفل‌شده: وضعیت، بدنه و هدرها **یکسان**؛ و ثابت‌کن همه‌ی مسیرها یک verify argon2 اجرا می‌کنند (spy، نه تست زمانی شکننده).
3. قفل: ۵ شکست ← ۴۲۹ + `Retry-After` برای موجود و ناموجود؛ رمز درست در قفل رد می‌شود؛ بعد از انقضا (دستکاری TTL) کار می‌کند؛ شمارنده‌ها صفر می‌شوند. سقف IP.

**Refresh و نشست** 4. چرخش؛ استفاده‌ی مجدد خارج از مهلت ← کل خانواده باطل + Audit؛ داخل مهلت ← ۴۰۱ بدون ابطال خانواده. 5. ۱۰ refresh هم‌زمان با یک توکن ← دقیقاً یک موفق و بقیه ۴۰۱ و خانواده زنده. 6. سقف مطلق ۹۰ روز و انقضای ۳۰ روز (دستکاری زمان‌ها در دیتابیس)؛ سقف ۱۰ نشست. 7. خروج ← توکن دسترسی **همان لحظه** رد؛ `logout-all`؛ تغییر رمز سایر نشست‌ها را باطل می‌کند و نشست جاری ادامه می‌دهد؛ غیرفعال‌سازی کاربر (با نوشتن مستقیم) و `revoked-before`.

**توکن و ایزولاسیون** 8. امضای غلط، `alg: none`، الگوریتم دیگر، منقضی، `aud` ادمین، `db` غیرمنطبق، نبود `sid`، توکن دیتابیس A با هدر/Host دیتابیس B ← ۴۰۱؛ توکن بدون هدر `X-Database` دیتابیس خودش را انتخاب می‌کند و داده‌ی دیتابیس دیگر هرگز نمی‌آید. 9. دو دیتابیس با کاربر هم‌نام و رمز متفاوت: ورود فقط در دیتابیس خودش؛ دو کوکی `bodo_rt_<slug>` مستقل در یک کلاینت. 10. توکن کاربر روی `/v1/admin/*` و توکن ادمین روی مسیر tenant ← رد.

**گاردها و مجوز** 11. مسیر آزمایشی بدون دکوراتور ← ۴۰۱ (امن‌بودن پیش‌فرض)؛ `@Public` باز؛ `@PortalOnly` در برابر `@InternalOnly`؛ `PermissionGuard` در حالت `any`/`all`؛ گروه سیستمی همه‌ی مجوزها از جمله مجوزی که در تست در زمان اجرا ثبت می‌شود؛ ابطال کش مجوز. 12. `mustChangePassword`: فقط سه مسیر مجاز؛ بقیه `PASSWORD_CHANGE_REQUIRED`؛ بعد از تغییر رمز آزاد.

**رمز عبور و امنیت** 13. مرز سیاست رمز (۹/۱۰/۱۲۸/۱۲۹)، NFKC، یونیکد، رمز رایج، برابر نام کاربری، بدنه‌ی بزرگ قبل از هش؛ rehash با پارامتر قدیمی. 14. CSRF: `Origin` غیرمجاز روی refresh و logout با کوکی ← ۴۰۳؛ حالت mobile بدون کوکی کار می‌کند. 15. قطع Redis (شبیه‌سازی) ← مسیرهای auth و مسیر محافظت‌شده ۵۰۳ و `/health/*` پاسخ می‌دهد. 16. Audit: هر رویداد یک ردیف دارد؛ هیچ رمز/توکن/نام کاربری خام در `audit_logs` و لاگ‌ها (`expectNoSecrets` و اسکن متنی). 17. بار: ۲۰ ورود هم‌زمان، `/health/live` در این بین زیر یک ثانیه جواب می‌دهد (argon2 حلقه‌ی رویداد را بلاک نمی‌کند).

**مایگریشن و قرارداد** 18. `0002_auth_sessions` روی دیتابیس تازه، روی `erp_dev` و روی دیتابیسی ساخته‌شده با Database Manager (`upgradeAll`)؛ `db:check-drift` سبز؛ ساخت دیتابیس جدید با Provisioning هنوز کار می‌کند. 19. ساختاری: هر `@Controller` به‌جز لیست مجاز صریح، یا گارد پیش‌فرض را دارد یا `@Public`؛ OpenAPI شامل `bearer` و خروجی auth بدون فیلد حساس.

**CI:** همه‌ی تست‌ها، همان دستورها و **بدون pipe که کد خروج را پنهان کند**. روی ماشین ویندوز من هم اجرا شود.
