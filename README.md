# سامانه bodo (ERP بازرگانی آهن‌آلات)

> **bodo** یک سامانه‌ی جامع، سریع و سبک ERP برای مدیریت تخصصی بازرگانی آهن‌آلات است که با NestJS، React و PostgreSQL در قالب یک مونوریپوی ساخت‌یافته (pnpm + Turborepo) پیاده‌سازی شده است.  
> اصل کلیدی معماری سیستم: **هر شرکت یک پایگاه‌داده‌ی کاملاً مستقل (Multi-Tenancy بدون `company_id` و بدون RLS)**.

---

## ۱. پیش‌نیازها

پیش از راه‌اندازی، مطمئن شوید نرم‌افزارهای زیر روی سیستم (ویندوز) نصب هستند:

- **Node.js**: نسخه ۲۴ LTS (نسخه ۲۴.۱۲ به بالا)
- **Docker Desktop**: فعال و در حال اجرا (برای کانتینرهای PostgreSQL و Redis)
- **PowerShell**: نسخه ۵ به بالا یا PowerShell 7 (pwsh)

---

## ۲. راه‌اندازی و فعال‌سازی ابزارها (PowerShell)

### ۲.۱. فعال‌سازی مدیر بسته (pnpm)

سیستم از `pnpm` استفاده می‌کند. برای فعال‌سازی آن با `corepack` در PowerShell:

```powershell
corepack enable pnpm
```

> **نکته در صورت خطای دسترسی ادمین در ویندوز:**  
> اگر اجرای دستور فوق به دلیل دسترسی ناموفق بود، می‌توانید PowerShell را به‌صورت Administrator باز کرده و دستور زیر را اجرا کنید، یا pnpm را مستقیماً نصب نمایید:
>
> ```powershell
> npm install -g pnpm
> ```

### ۲.۲. آماده‌سازی فایل متغیرهای محیطی

یک کپی از فایل نمونه پیکربندی بسازید:

```powershell
Copy-Item .env.example .env
```

### ۲.۳. نصب وابستگی‌های مونوریپو

در ریشه‌ی پروژه دستور زیر را اجرا کنید:

```powershell
pnpm install
```

## ۳. اجرای پروژه در محیط توسعه (Dev Mode)

برای توسعه محلی، پایگاه‌داده و ردیس با داکر بالا می‌آیند و برنامه‌های `api` و `web` روی ماشین محلی اجرا می‌شوند.

> **نکته پورت دیتابیس در حالت توسعه (Port 5433):**  
> برای جلوگیری از تداخل با PostgreSQL محلی ویندوز (که معمولاً روی پورت 5432 گوش می‌دهد)، کانتینر دیتابیس توسعه روی پورت `5433` هاست (فقط روی `127.0.0.1`) متصل می‌شود. ردیس نیز روی پورت `6379` مقید به `127.0.0.1` است.

> **یادداشت مهاجرت نام پروژه‌های Docker Compose (گام S1.3):**  
> برای جلوگیری از هشدارهای orphan و تداخل، فایل اصلی دارای `name: bodo` و فایل توسعه دارای `name: bodo-dev` است. اگر از نسخه‌های قبل کانتینری باقی مانده بود، یک‌بار دستور `docker compose -p infra down` را اجرا کنید. سپس دیتابیس محلی را با `pnpm db:setup-dev` (یا اجرای `db-setup.bat`) بسازید.

### ۳.۱. اجرای سرویس‌های پایه (PostgreSQL و Redis)

```powershell
docker compose --env-file .env -f infra/docker-compose.dev.yml up -d
```

### ۳.۲. اجرای هم‌زمان تمام اپلیکیشن‌ها (API + Web)

```powershell
pnpm dev
```

- **برنامه تحت وب (فرانت‌اند):** `http://localhost:5173`
- **سرویس API (بک‌اند):** `http://localhost:3000`
- **بررسی سلامت سیستم (Live):** `http://localhost:3000/health/live`
- **بررسی اتصال دیتابیس و ردیس (Ready):** `http://localhost:3000/health/ready`

### ۳.۳. اجرای Storybook (محیط ایزوله کامپوننت‌های UI)

```powershell
pnpm --filter @bodo/ui storybook
```

- آدرس Storybook: `http://localhost:6006`

## ۴. اجرای آزمون‌ها و بررسی کیفیت کد

تمام فرامین زیر در ریشه پروژه قابل اجرا هستند:

```powershell
# بررسی خطاهای تایپ‌اسکریپت در تمام بسته‌ها
pnpm typecheck

# بررسی و اصلاح خودکار استایل کد (Lint)
pnpm lint

# اجرای کلیه تست‌های واحد و یکپارچگی (Jest برای API و Vitest برای Web/Packages)
pnpm test

# بیلد کامل تمام بسته‌ها و برنامه‌ها
pnpm build

# فرمت‌بندی کدها با Prettier
pnpm format
```

## ۵. اجرای کامل با Docker Compose (مشابه محیط تولید)

برای اجرای تمامی سرویس‌ها (Postgres، Redis، API، Worker و Web/Nginx) در قالب کانتینر:

```powershell
docker compose -f infra/docker-compose.yml up --build -d
```

### بررسی وضعیت کانتینرها و سلامت:

```powershell
docker compose -f infra/docker-compose.yml ps
```

- سامانه وب از طریق پورت ۸۰: `http://localhost`
- اندپوینت‌های API از طریق Reverse Proxy Nginx: `http://localhost/health/live` و `http://localhost/health/ready`

برای خاموش کردن سرویس‌ها:

```powershell
docker compose -f infra/docker-compose.yml down
```

## ۶. اجرا با دابل‌کلیک در ویندوز (Windows Launchers)

برای راحتی کار، فایل‌های اجرایی دسته‌ای (`.bat`) در ریشه‌ی پروژه و پوشه‌ی `scripts/windows/` قرار دارند تا بدون نیاز به تایپ دستی دستورات، با دابل‌کلیک پروژه را اجرا یا متوقف کنید:

| نام اسکریپت          | عملکرد                                                                                                                                                      |
| :------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`start.bat`**      | اجرای کل سامانه با Docker Compose (مشابه پروداکشن)، انتظار تا سالم شدن کانتینرها، و باز کردن خودکار مرورگر روی `http://localhost`.                          |
| **`stop.bat`**       | متوقف کردن امن تمام کانتینرهای در حال اجرا بدون حذف اطلاعات یا ولوم‌های دیتابیس (`docker compose stop`).                                                    |
| **`dev-start.bat`**  | بالا آوردن کانتینرهای دیتابیس و ردیس توسعه (پورت‌های ۵۴۳۳ و ۶۳۷۹)، باز کردن پنجره‌ی اختصاصی برای `pnpm dev`، و باز کردن مرورگر روی `http://localhost:5173`. |
| **`dev-stop.bat`**   | بستن درخت پردازه‌های توسعه `pnpm dev` (شامل Vite و NestJS) و متوقف کردن کانتینرهای دیتابیس توسعه.                                                           |
| **`status.bat`**     | نمایش وضعیت سلامت کانتینرها (`docker compose ps`) و ارسال درخواست تست به اندپوینت `/health/ready`.                                                          |
| **`logs.bat`**       | نمایش لاگ‌های زنده‌ی کانتینرها به صورت لحظه‌ای (`docker compose logs -f --tail 100`).                                                                       |
| **`db-setup.bat`**   | آماده‌سازی پایگاه‌داده توسعه `erp_dev`، ساخت نقش‌ها، اعمال مایگریشن‌ها و داده‌های اولیه.                                                                    |
| **`db-manager.bat`** | رابط خط فرمان مدیریت پایگاه‌های داده (ایجاد، کپی، پشتیبان‌گیری، بازیابی، تعمیر، مهاجرت و نگاشت دامنه).                                                      |

### ۶.۱. ابزار خط فرمان مدیریت پایگاه‌داده (Database Manager CLI)

از طریق `pnpm db:manager` یا اجرای لانچر `db-manager.bat` می‌توانید عملیات مدیریتی پایگاه‌های داده چندمستاجری را مدیریت کنید:

```powershell
# فهرست شرکت‌ها و پایگاه‌های داده
pnpm db:manager list

# ایجاد شرکت و پایگاه‌داده‌ی جدید
pnpm db:manager create acme --user admin --name "مدیر اصلی" --watch

# پشتیبان‌گیری از پایگاه‌داده (شامل دیتابیس، فایل‌ها و مانیفست sha256)
pnpm db:manager backup acme --watch

# کپی کردن پایگاه‌داده (تست یا محیط Staging)
pnpm db:manager duplicate acme acme_test --watch

# بازیابی پایگاه‌داده از فایل فشرده
pnpm db:manager restore acme_restored ./backups/acme/backup-20261113.zip --watch

# تعمیر و رفع قفل دیتابیس‌های معلق یا شکست مایگریشن
pnpm db:manager repair acme --confirm

# نگاشت دامنه اختصاصی به پایگاه‌داده
pnpm db:manager domain acme acme.steel.example

# مشاهده‌ی لاگ ممیزی امنیتی عملیات ادمین (Audit Trail)
pnpm db:manager audit --tail 50
```

> **امنیت رمزهای عبور در CLI:**  
> در دستور `create`، پیشنهاد می‌شود رمز عبور ادمین شرکت را با پرامپت مخفی وارد کنید یا از متغیر محیطی `ADMIN_PASSWORD` استفاده نمایید. استفاده از فلگ `--pass` در صورت تمایل امکان‌پذیر است، اما به دلیل خطر ثبت در تاریخچه‌ی خط فرمان (Shell History)، هشدار امنیتی نمایش داده خواهد شد.

### ۶.۲. لاگ ممیزی و مسیر فایل‌ها (Admin Audit Trail & Volumes)

تمامی عملیات‌های حساس مدیریت پایگاه‌داده (شامل شروع عملیات، ثبت جاب، اتمام موفقیت‌آمیز یا شکست، ورودهای ناموفق و نقض لیست مجاز IP) با شناسه درخواست (`requestId`)، آدرس IP درخواست‌دهنده (`actorIp`) و شناسه‌ی پردازش (`jobId`) در فایل لاگ ساخت‌یافته‌ی JSONL ذخیره می‌شوند. تمامی اطلاعات حساس مانند رمزهای عبور و توکن‌ها قبل از ثبت به صورت `******` ماسک می‌شوند.

- **مسیر محلی لاگ ممیزی:** `data/logs/admin-audit.log`
- **مسیر ولوم در داکر:** کانتینرهای `bodo-api` و `bodo-worker` ولوم نام‌گذاری‌شده‌ی `logs` را در مسیر `/data/logs` ماونت می‌کنند (`logs:/data/logs`).
- **محدودیت دسترسی بر اساس IP (Allowlist):** متغیر `DB_MANAGER_ALLOWED_IPS` لیست IPهای مجاز را مشخص می‌کند. در محیط Docker Desktop روی ویندوز، بسته‌های وارده ممکن است با آدرس دروازه‌ی شبکه پل داکر (مثلاً `172.20.0.1` یا `172.18.0.1`) برسند؛ برای سهولت دسترسی در محیط توسعه، این رنج‌ها یا `127.0.0.1` به طور پیش‌فرض در تنظیمات مجاز شمرده شده‌اند.

> **نکته امنیتی و تولید خودکار `.env`:**  
> اگر فایل `.env` در سیستم شما وجود نداشته باشد، این اسکریپت‌ها پیش از اجرا آن را به‌طور خودکار بر اساس `.env.example` می‌سازند، تمامی پسوردها و کلیدهای رمزنگاری را با مقادیر تصادفی و امن پر می‌کنند و رمز اصلی (Master Password) اولیه را در کنسول به شما اعلام می‌نمایند. اگر فایل `.env` از قبل موجود باشد، به هیچ وجه تغییر نمی‌کند.

## ۷. ساختار مونوریپو

```
.
├── apps/
│   ├── api/            # بک‌اند NestJS (اندپوینت‌های سلامت، مانیتورینگ، لاگر pino)
│   └── web/            # فرانت‌اند React + Vite (RTL، فونت وزیرمتن خودمیزبان، Tailwind)
├── packages/
│   ├── contracts/      # شِماهای اعتبارسنجی Zod و قراردادهای API
│   ├── ui/             # کتابخانه‌ی کامپوننت‌های رابط کاربری + Storybook
│   └── utils/          # توابع کمکی مشترک
├── docs/               # مستندات فنی، قوانین و سوابق تصمیمات معماری (ADRs)
└── infra/              # پیکربندی Docker Compose، Nginx و اسکریپت‌های آغازین دیتابیس
```
